# RepoGuide — Onboarding Dashboard (Hackathon Demo)

A React frontend that presents **pre-generated onboarding guides** produced by **IBM Bob**.  
It does **not** analyse repositories live — it displays structured JSON that Bob generates
in the IBM Bob IDE.

---

## Quick start

```bash
cd repoguide-ui
npm install        # first run only
npm run dev        # starts Vite dev server
```

Open **http://localhost:5173** in your browser.

---

## Demo walkthrough

1. **Landing page** — Three preset repositories are shown as cards.
2. **Select a repo** — Click a card marked **"Bob output ready"** to load its guide.
3. **Dashboard** — Navigate the 7 sections using the left sidebar.
4. **Switch repos** — Use the dropdown in the topbar or click **← All repos** in the sidebar.
5. **Search** — Type in the search bar to filter and highlight content across all sections.
6. **Pending repos** — Cards marked **"Guide pending"** are visibly disabled. Their Bob output
   has not been generated yet.
7. **GitHub links** — Every card and the dashboard header link directly to the real GitHub repo.

> **Honest labelling:** A green "Demo" banner on every guide page makes clear that the guide
> was prepared in advance and that no live analysis is running.

## Adding a guide for a pending repository

1. Generate the onboarding package in IBM Bob and export it as JSON.
2. Save the file in `public/` (e.g. `public/onboarding-realworld-react.json`).
3. Open [`src/lib/repos.ts`](src/lib/repos.ts) and update the matching entry:
   ```ts
   {
     id: 'realworld-react',
     // ...
     status: 'ready',           // change from 'pending'
     jsonPath: '/onboarding-realworld-react.json',  // add the path
   }
   ```
4. Restart or rebuild — the card will now show "Bob output ready" and be clickable.

## JSON schema

All fields are required. The schema is defined in [`src/lib/loader.ts`](src/lib/loader.ts) —
update only that file when Bob changes the output format.

```
{
  "project":              { name, version, author, summary }
  "techStack":            [{ concern, technology }]
  "repositoryLayout":     [{ path, type, description }]
  "modules":              [{ name, title, responsibilities[], runCommand }]
  "dataFlows":            [{ name, steps[] }]
  "apiEndpoints":         [{ method, path, auth, description }]
  "dependencyWiring":     [{ dependency, definedIn, injectedInto, provides }]
  "notes":                string[]
  "databaseModel":        { table, columns[{ name, type, constraints }], warning }
  "localSetupChecklist":  string[]
  "howToAddNewModule":    string[]
  "knownGaps":            [{ area, gap }]
}
```

## What this frontend does NOT do

- It does **not** analyse repositories — that is IBM Bob's job.
- It does **not** accept arbitrary GitHub URLs or trigger any analysis.
- It does **not** connect to a backend, database, or AI service.
- It does **not** upload files or authenticate users.
- All JSON is pre-generated by Bob and served as static files.
